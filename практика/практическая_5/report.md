# Практическая работа. Переписать обработку большого массива с циклов на NumPy; сравнить время и читаемость

Окружение: Python 3.12.0, numpy 2.5.1, scipy 1.18.0, Windows 11.

Методика: `time.perf_counter()`, 3 прогона, берётся минимум (для n ≤ 10⁴ — среднее по 1000 вызовов внутри прогона). Данные — `np.random.default_rng(42)`. Цикл работает со списком Python (`a.tolist()` до замера), NumPy — с ndarray. SLOC — строки тела функции без пустых и комментариев. Память — пик по `tracemalloc`. Точные цифры времени меняются от запуска к запуску; порядок величин стабилен.

## Задача 7. Максимум и его индекс

| вариант | время | SLOC | результат совпадает |
|---|---|---|---|
| цикл Python | 24.98 мс | 7 |  |
| NumPy | 278.1 мкс | 1 | да |
| **ускорение** | **89.8×** |  |  |

Максимум 5.007235 на индексе 42665 — у обоих вариантов.

Те же данные с одним NaN:

| данные | цикл | `a.max()` | `np.nanmax` / `np.nanargmax` |
|---|---|---|---|
| NaN в начале (a[0]) | nan (idx 0) | nan | 5.007235 (idx 42665) |
| NaN в середине (a[500000]) | 5.007235 (idx 42665) | nan | 5.007235 (idx 42665) |

**Вывод.** Без NaN ускорение 89.8×, ответы совпадают. С NaN цикл ведёт себя непредсказуемо: любое сравнение с NaN даёт False. Если NaN стоит первым, он становится max_val, ни одно `x > nan` не срабатывает, и цикл возвращает NaN. Если NaN в середине, цикл его молча пропускает и случайно отвечает правильно. То есть результат зависит от того, где оказался пропуск. `a.max()` честно возвращает NaN (сигнал: «в данных дыра»), а `np.nanmax` осознанно пропускает NaN и даёт правильный ответ в обоих случаях. Функции с префиксом nan — защита от реальных данных: пропуски в измерениях бывают всегда, и поведение на них должно быть явным, а не зависеть от позиции.

## Задача 9. Замена по маске (in-place)

| вариант | время | ускорение | SLOC | тот же объект | доп. память | верно |
|---|---|---|---|---|---|---|
| цикл по list | 43.04 мс | 1× | 4 | да | — | да |
| `a[a < 0] *= -1` | 8.64 мс | 5.0× | 2 | да | 5.0 МБ | да |
| `np.abs(a, out=a)` | 284.6 мкс | 151× | 2 | да | 0.0 МБ | да |

«Тот же объект» проверен по id списка и по адресу буфера данных ndarray (`__array_interface__['data']`) до и после.

## Задача 10. Комбинированная маска

| вариант | время | SLOC | результат совпадает |
|---|---|---|---|
| цикл Python | 57.52 мс | 1 |  |
| NumPy | 3.73 мс | 1 | да |
| **ускорение** | **15.4×** |  |  |

Отобрано 682 890 элементов (≈68% — правило «одной сигмы»).

Что будет без скобок:

| данные | `a > -1 & a < 1` |
|---|---|
| float-массив | `TypeError: ufunc 'bitwise_and' not supported for the input types, and the inputs …` |
| int-массив | `ValueError: The truth value of an array with more than one element is ambiguous. U…` |

**Вывод.** Ускорение 15.4×. В Python `-1 < x < 1` — удобная цепочка сравнений, но для массива она не работает: цепочка `p < q < r` раскрывается в `(p < q) and (q < r)`, а `and` требует одно True/False от целого массива. Без скобок ещё хуже: `&` имеет более высокий приоритет, чем `<` и `>`, поэтому `a > -1 & a < 1` читается как `a > (-1 & a) < 1`. Для float побитовое `&` вообще не определено (TypeError), для int получается цепочка сравнений с массивом (ValueError про неоднозначную истинность). Поэтому в NumPy каждое условие берут в скобки и соединяют `&`, `|`, `~`. Это менее естественно, чем `-1 < x < 1`, — здесь чистый Python читается лучше.

# Блок 4. Реальные кейсы

## Задача 11. Матрица расстояний (n = m = 1000, точки в R³)

| вариант | время | ускорение | пиковая память | совпадает с broadcasting |
|---|---|---|---|---|
| двойной цикл | 329.87 мс | 1× | — | да |
| broadcasting (n, m, 3) | 22.12 мс | 14.9× | 48.0 МБ | — |
| через X @ Y.T | 5.69 мс | 58.0× | 24.0 МБ | max ошибка 9.9e-15 |
| `scipy.spatial.distance.cdist` | 2.54 мс | 130× | 8.0 МБ | да |

**Вывод.** Временный массив `X[:, None, :] - Y[None, :, :]` имеет форму (1000, 1000, 3): 3·10⁶ × 8 байт = 24 МБ, и ещё столько же уходит на квадраты — отсюда пик 48.0 МБ, хотя ответ занимает всего 8 МБ. Broadcasting быстрее цикла в 14.9×, но платит памятью: при n = m = 10⁴ временный массив был бы уже 2.4 ГБ. Формула ‖x − y‖² = ‖x‖² + ‖y‖² − 2·x·y сводит работу к матричному умножению (пик 24.0 МБ), но вычитает близкие числа: здесь ошибка до 1e-14 по модулю, а для очень близких точек относительная ошибка становится большой (отсюда np.maximum(d2, 0) против отрицательных d2). cdist считает расстояния в C без временных массивов: и быстро (130×), и экономно (8.0 МБ). Компромисс: broadcasting — самый короткий и понятный код, но память растёт как n·m·d. Для больших данных нужны cdist или обработка блоками.

## Задача 12. Скользящее среднее (n = 10⁵, k = 10)

| вариант | сложность | время | ускорение | SLOC | совпадает |
|---|---|---|---|---|---|
| двойной цикл | O(n·k) | 42.01 мс | 1× | 7 | — |
| `np.convolve(..., mode='valid')` | O(n·k) | 181.8 мкс | 231× | 1 | да |
| через `np.cumsum` (доп.) | O(n) | 331.5 мкс | 127× | 2 | ошибка 2e-14 |

**Вывод.** np.convolve выполняет те же n·k ≈ 10⁶ умножений-сложений, что и двойной цикл, — асимптотика та же, O(n·k). Ускорение 231× берётся только из константы: одна операция в C стоит доли наносекунды, а в интерпретаторе — десятки наносекунд. Это не алгоритмическое улучшение, но на практике его достаточно: 10⁵ точек обрабатываются за 181.8 мкс. Настоящее улучшение алгоритма — префиксные суммы (O(n), не зависит от k). Но при маленьком k = 10 оно даже медленнее, чем convolve (331.5 мкс против 181.8 мкс): лишние проходы по памяти и временные массивы съедают выигрыш, он появится при больших k. И за него платим точностью: разность больших накопленных сумм даёт ошибку 2e-14.

## Задача 13. Кумулятивная сумма (n = 10⁵)

| вариант | время | SLOC | результат совпадает |
|---|---|---|---|
| цикл Python | 3.41 мс | 6 |  |
| NumPy | 259.4 мкс | 1 | да |
| **ускорение** | **13.1×** |  |  |

| способ | последний элемент / полная сумма | ошибка относительно math.fsum |
|---|---|---|
| math.fsum (точная сумма) | -423.293027892284101 | — |
| цикл: result[-1] | -423.293027892283476 | 6.3e-13 |
| np.cumsum(a)[-1] | -423.293027892283476 | 6.3e-13 |
| a.sum() (попарное суммирование) | -423.293027892284044 | 5.7e-14 |

**Вывод.** Ускорение 13.1×, совпадение до 1e-9 выполнено с запасом: максимальное расхождение цикла и np.cumsum — 0.0e+00 (побитово одинаково). ## Задача 15. Полный кейс: обработка «сырых» измерений (10⁵ × 3)

| шаг | время цикла | время NumPy | ускорение | SLOC цикл / NumPy | результаты совпадают |
|---|---|---|---|---|---|
| 1. найти выбросы: abs(x − mean) > 5·std | 91.97 мс | 4.00 мс | 23.0× | 17 / 1 | да |
| 2. выбросы → NaN → среднее столбца | 66.93 мс | 4.19 мс | 16.0× | 14 / 2 | да |
| 3. нормировка столбцов | 82.70 мс | 4.04 мс | 20.5× | 13 / 1 | да |
| 4. mean и std после нормировки | 50.05 мс | 3.42 мс | 14.6× | 12 / 1 | да |
